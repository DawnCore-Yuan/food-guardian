## 一、音效

### 1.1 最初無聲的原因

**[程式／測試證實]** 實際播放路徑 `spawn()` 中，voice GainNode 初值為 `0`，且該層沒有任何音量包絡排程，
導致整條輸出鏈被乘成 0。同一 OfflineAudioContext 的階梯量測：

| 結構 | peak |
|---|---|
| 固定 gain 0.5 對照音 | 0.5 |
| 加包絡、voice 直接接 destination | 0.0995 |
| 完整 spawn 結構（voice gain = 0） | **0** |

**[人工確認]** 初值改為 `1` 後（commit `82a3199`），使用者確認有聲。

### 1.2 第二次回歸

**[人工確認]** `83f9239` 同時改動音色與聲源容量管理後，使用者回報再次無聲。
**[人工確認]** `da202e2` 單檔還原 `src/systems/audio.ts` 後，使用者確認恢復。

**[未確認]** 具體原因未隔離。**不可**歸因於音色或容量管理其中任一項。

### 1.3 四層證據必須分開

| 層級 | 能證明 | 不能證明 |
|---|---|---|
| 觸發 | 事件有呼叫播放 | 有沒有聲音 |
| 排程（`scheduled`） | 節點已 `start()` | 有沒有聲音 |
| 非零波形（OfflineAudioContext） | 合成與包絡會產生樣本 | 裝置是否出聲 |
| 實際聽到 | 真的有聲音 | 其他裝置是否一樣 |

`AudioContext.state === 'running'` 只代表 context 在跑，不是有聲的證據。

### 1.4 離線測試的界線

**[程式／測試證實]** 離線渲染另寫一份近似實作時，結果無法代表正式播放路徑；
且離線渲染本身不會經由喇叭發聲。要能代表正式路徑，必須呼叫管理器自己的合成函式。

### 1.5 變更要分開

一次只改一類：音色、容量管理、解鎖、輸出鏈。各自 commit、各自 build、各自交付實聽。
本次因兩類同時進入，事後無法區分，只能整檔還原。

### 1.6 回歸處理

保存「已人工確認有聲」的 commit。回歸時用
`git checkout <已知有聲 commit> -- src/systems/audio.ts`，
不 `reset --hard`、不整專案退版。

### 1.7 清理語意不可拆

暫停、靜音、切背景、結算、重玩的停止與釋放邏輯保留。
不可為了「讓聲音出來」移除 `stopAll`／suspend 保護。

### 1.8 診斷頁

**[程式／測試證實]** 診斷頁必須是 Vite 建置入口，由 Vite 編譯成 dist chunk；
不能讓 `dist` 頁面 import 未建置的 `/src/*.ts`（會 `Failed to fetch dynamically imported module`）。

### 1.9 人工確認的範圍

**[人工確認]** 只記錄「使用者實測的那台裝置與版本」，不外推其他裝置、瀏覽器或系統。

## 二、首頁音效按鈕

### 2.1 初始化與點擊共用同一繪製函式

**[程式／測試證實]** 本次漏呼叫 `paintSnd()`，造成首次只有白字、點擊後才出現橢圓。
建立物件與尺寸後應立即依既有偏好繪製一次；**只讀偏好，不切換**。

### 2.2 五種情境要分別驗

首次載入、儲存為開、儲存為關、連續切換、返回首頁。
本次只驗了前四種中的前三種（返回首頁未實測）。

### 2.3 五個量要分開

字級（`fontSize`）、文字實際尺寸（`getBounds()`）、底板尺寸、命中區尺寸、
邏輯像素與 CSS 像素。只放大命中區不代表文字變大。

### 2.4 檢查縮放

同時檢查文字與父容器的 `scaleX`／`scaleY`。兩層都是 1，才能說「大小由字級決定」。

### 2.5 本次採用固定字級

**[程式／測試證實]** 最終採 40px，與「開始遊戲」一致：桌面文字 132×46、底板 192×80。

**[未確認]** 先前「100px 量測反推字級」未達預期（實測算出 26px）。
**[未確認]** 「Phaser 必須等下一幀才更新尺寸」證據不足，**不得寫成引擎定律**。

## 三、HUD 排版

### 3.1 由右往左預留

**[程式／測試證實]** 先預留 暫停鈕 → gap → 音效鈕 → gap → 完整時間欄位 → gap → 進度條，
再用剩餘空間決定進度條寬度。

### 3.2 用完整矩形判斷重疊

同一座標系的 `left/top/right/bottom`。只比點座標會漏掉邊界相接的情況：
本次曾因時間右緣與音效鈕右緣同點而誤判「不重疊」。

實測（桌面 1280×720）：

| 元素 | 左 | 右 |
|---|---|---|
| 進度條 | 577.7 | 943 |
| 時間欄位 | 970 | 1117 |
| 音效鈕 | 1133 | 1185 |
| 暫停鈕 | 1197 | 1249 |

### 3.3 手機命中區

**[程式／測試證實]** 以 canvas 實際 CSS 比例換算，目標 ≥48×48 CSS px；
實測 48.7×48.8。resize 或方向改變後需重算。

### 3.4 正式版照樣可驗

**[程式／測試證實]** 正式包沒有 dev 掛鉤，仍可用截圖與畫面座標點擊驗證；
不應因此要求新增 debug build。

### 3.5 產物對帳

最終核對三處：`dist/index.html` 引用的完整檔名、磁碟上的檔案、preview 實際回傳的檔名。
